# Cedar / Maple 示例设计约定

适用于两库组件文档、独立示例集合和可复制源码。

文档仅保留组件用途、操作步骤、公开行为和必要限制；内部授权、交接、审计批次、测试通过数及证据路径放在 `design-ui/audits/`，不进入用户页面。`archive-demo-maintenance-notes.mjs` 只读检查这些过程说明，`--write` 归档后移出页面，API 表、代码和 demo 引用不参与清理。

源码复制策略、内部类名变更、源码一致性检查及测试验收记录同样归入内部审计。公开页面保留实际使用所需的升级迁移、键盘交互、事件顺序、平台限制及生命周期行为；样式变量默认值和使用边界归入 `CSS Variables`。`clean-public-component-docs.mjs` 按已人工复核的段落清理并归档，两端 `check:doc-pipeline` 检查清理结果及中英文一致性；新增可疑段落应人工判断，不按关键词直接删除。

基础案例在前，尺寸、变体和状态随后，异步、复杂插槽及生命周期案例在后；功能调试仅供内部验证，不进入公开文档或移动示例集合。同组件的跨端共有案例遵守同一相对顺序，平台独有案例保留。说明章节跟随所解释的案例，不得因为存在无 demo 的章节而跳过整页；FormItem 等独立章节保留边界。整理脚本须重复运行不产生差异。

组件示例按功能分组，使用二级标题表示分组、三级标题表示案例；不把所有功能堆在唯一的“案例 / Examples”分组下。第一组为“基础示例 / Basic examples”，首例使用最少配置；之后按组件自身功能从简单到复杂、从静态展示到交互控制、异步数据与业务组合排列。同类能力放在同一组，不要求所有组件使用相同数量或名称的组，也不为每个案例单独创建一组。示例集中在 API 之前，相关说明随案例移动。

Cedar 的中英文分组和组内顺序维护于 `design-ui/configs/demo-groups.json`，Maple 对应 `demo-groups.maple.json`。两端旧文件名的对应关系维护于 `demo-case-aliases.maple.json`；相同能力使用相同分组和相对顺序，平台独有案例保留。运行 `node design-ui/bin/organize-component-showcase.mjs --write` 同时整理两端文档和 Maple 手机示例入口。

新增案例须明确所属分组，检查模式拒绝未分组或重复分配的案例；整理前后必须保留全部公开 demo 引用及 API 表格。每个组件须有可运行的基础示例，不使用空入口占位。Maple 的文档与独立手机示例应引用同一批场景，手机示例同步展示中英文分组标题，不能只调整 Markdown。说明性布局指南保留在基础组；组合页面中的独立面板 API 保留专属 API 章节，不混入示例卡片。

全量门禁：`node --test design-ui/bin/group-demo-sections.test.mjs design-ui/bin/group-maple-examples.test.mjs` 检查所有组件文档、基础示例、手机入口、分组完整性、源码对应、跨端共有案例顺序及整理幂等性；不得以少数样本代替全量清单。

Cedar 文档开发服务只能有一个进程写入同一临时目录，不能仅通过换 host 或端口启动第二份。页面生成采用同路径串行、原子替换并跳过内容不变的写入；不通过吞掉 `updatePageData` 异常掩盖半写入文件。修改组件文档或 demo 后，应在不手动刷新的情况下检查正文、展开源码和中英文页面更新。

- 一张示例围绕一类功能。允许组合最多三个相关维度，例如 Button 的变体、状态色、尺寸；不把值模型、异步请求、插槽、布局等全部装进同一个控制台。
- 同类取值放在同一张卡片对比。五档尺寸、八种状态色不各拆五张或八张卡片。
- 首个示例能直接运行，保留必要的值绑定和最少配置。常规功能在前，复杂业务和生命周期案例在后；公开示例不包含功能调试控制台。
- 共同 API 使用一致的案例名称、操作顺序、输入数据和说明；Cedar 的鼠标键盘行为、Maple 的触摸及弹层形态可分别演示。
- 每个新案例说明使用场景、操作方法和预期结果；异步场景使用本地可控数据，上传展示不默认向远端发送文件。
- 示例源码就是实际运行文件。Markdown、源码展示和独立集合引用同一 SFC，新增或合并后同步中英文标题与引用。
- 控制区始终可操作，禁用或只读的目标控件不能把恢复入口一起禁用；切换功能分类清除旧覆盖和事件记录。
- 示例控制区使用 Form/FormItem 组织字段标签和宽度，Space 管理间距，Card/Paper 承载外观对照。少量固定的互斥选项优先使用 RadioGroup 直接展示；较长或需要搜索的选项列表使用 Select，并由表单布局提供可用宽度。
- 保留明确的综合业务案例，例如 Scheduler 工单编辑，但将其排在基础功能之后，并说明完整业务目标。
- Space 仅使用公开的 `row` / `column` 方向；横向对比区显式允许换行。示例在 346px 预览内不得撑宽页面，Grid 列使用 `minmax(0, 1fr)` 避免内容最小宽度反向撑开。需要横向比较的表格、时间线可使用明确的组件内滚动区，不通过全局裁剪隐藏问题。
- 无 SDK、权限或业务接口时，首例提供清晰降级状态与本地可操作模型，不在 mounted 中调用未初始化服务，也不硬编码凭据、占位远端图片或自动申请定位权限。
- 图片错误态和回退示例使用确定的损坏内联数据（如 `data:image/png;base64,AA==`）触发解码失败，不请求不存在的 HTTP 图片；保留真实错误态与回退断言，不为演示制造站内 404 或在浏览器门禁中过滤它。
- 空白判断必须检查实际组件 DOM，不能把无文字的图标、评分等控件认定为空案例。亮暗、源码、鼠标键盘、真实触摸和外部服务的验收级别分别记录。

本地参考：Element Plus 的 Button 同类取值对比、Naive UI 的加载交互和独立禁用示例。采用其便于比较、可操作的组织方法，组件 API 仍遵守本项目公共契约。

验证命令：`node design-ui/bin/demo-design-check.mjs` 检查全量 SFC 和文档引用；`node design-ui/bin/organize-demo-pages.mjs` 检查组织结果；共享预览的测试覆盖分类切换，新案例运行测试覆盖真实组件挂载和属性切换。

### 合并示例后的内容验收

逐组件审查重复场景和独有交互，记录保留或合并的依据。关联配置应围绕同一任务对比；外观和值绑定使用同一份模型，弹层等独立场景保留各自开关。合并后的说明须包含操作、配置差异和预期结果，不能用重复代码的包装页面代替内容重构。

中英文引用集合、Maple 手机入口和源码展示必须同步。全量运行 `demo-content-parity.test.mjs`、分组与 SFC 检查；对实际合并的示例挂载真实组件，验证事件、值更新和状态恢复。浏览器按组件与语言检查真实手机路由、完整场景集合和窄屏布局，并对表单、轮播、分页、弹层等代表性流程进行原生交互。记录来源、视口、实测结果和覆盖边界，不能把编译成功描述为交互验收。
