## 真实交互与修复

1. 初始已保存 3 条。点击“复制评审会议”后打开新日程草稿；点击取消，抽屉关闭且仍为 3 条。
2. 旧 Demo 勾选“模拟副本保存失败”后，保存报错并保留草稿，但开关仍勾选且位于模态抽屉外，无法直接关闭失败模拟来重试。此前测试通过直接发出 Checkbox 更新事件绕开抽屉，漏掉实际操作路径。
3. 将该模拟改成“下一次副本保存失败”：提交前捕获并自动复位一次性标记，当前请求仍按捕获值失败。失败仍保留原模型和草稿，再点击抽屉内保存即可成功。
4. 新生产文档实际点击：勾选一次性失败 → 复制评审会议 → 保存，显示“保存失败，请重试”、已保存仍为 3 条、抽屉保留标题和时间、外部开关已复位；无需关闭抽屉直接再次保存，变为 4 条，抽屉关闭，撤销入口启用。截图：`/private/tmp/cedar-scheduler-copy-retry-batch49.png`。

这仅修复 Demo 的本地模拟开关，不改变 Scheduler 运行时、复制 API 或业务服务。第三条同时预约的容量限制、全天/未排期复制的实际浏览器保存、撤销/重做及其他 Scheduler 高级组合仍未验收。
