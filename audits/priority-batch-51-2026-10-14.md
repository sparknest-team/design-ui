# 第五十一批：Scheduler 异步资源回显与重试反馈

## 范围

- Cedar 生产文档站 `/components/scheduler/` 的“异步目录、分页与 ID 回显” Demo；Maple 无 Scheduler 对应组件。
- 使用示例内的合成设备/人员目录和本地延迟请求，不接真实接口。本批仅修 Demo 的状态反馈，不改变 Scheduler 资源 API 或运行时。

## 真实浏览器交互

1. 已有关联 `device-12` 不在当前 4 条资源中，页面仍通过 ID 回显为“实验设备 12”。
2. 点击“模拟回显失败并重新加载”：卡片回退显示 `device-12`，资源错误提示和示例失败状态出现，关联 ID 未消失。点击日程内“资源加载失败，点击重试”后恢复“实验设备 12”，错误提示消失，示例状态转为“资源名称回显成功，关联 ID 保持不变”。
3. 设置下次搜索失败，打开该日程的编辑器及设备下拉框：搜索失败时出现重试按钮。点击重试后候选项“实验设备 1–4”恢复，示例状态转为“搜索重试成功，可继续选择资源”。取消编辑器后原日程保持不变。
4. 切换为“人员接口”：同一 ID 反显“工程师 12”，资源类型变为人员，旧搜索状态重置为初始提示。此前还实际搜索“12”并加载更多，确认选中项 12 与第 1–8 条分页候选可共存；此部分是在修复前产物上验证，修复后没有重复测试分页。

## 发现与修复

旧 Demo 的失败状态是一次性写入的：资源请求成功后，组件内错误已恢复，但外层 Demo 文案仍显示“失败”；切换设备/人员接口也延续旧文案。现在记录失败请求类型，仅在相应请求成功时清除失败提示，切换目录时重置反馈。回显失败提示也明确指向日程内的重试按钮。
