# 第一百零三批：Cedar Form 异步改值观察与路由清理

## 真实浏览器动作及结果

使用第九十八批成功完整构建的本地 `components/form/?audit=103-built`，操作现有“表单异步校验” Demo。仅使用本地 guest/admin 合成值，规则延迟 600ms，不访问外部服务。

1. 快速输入 guest、Enter 提交、立即改为 admin、再 Enter，观察到“校验中；活动校验：3”，模型已为 admin。最终显示“未通过；活动校验：0”，用户名输入没有 aria-invalid 和残留字段错误。加载中的提交按钮会阻止原生重复提交，未证明第二次 Enter 成功发起新提交，因此不把此结果计为“最新提交获胜”或旧校验覆写模型的缺陷；它只说明旧提交结果与当前已修改模型可能不同。
2. 在 admin 稳定值上明确点击提交，观察活动校验 1，随后“通过；活动校验：0”，模型仍为 admin，可正常重试。
3. 实际离开再返回 Form 后，从初始空模型开始，输入 guest 并 Enter，观察到“校验中；活动校验：2”，随后通过左侧 Button 菜单离开，确认异步 Demo 已消失且 URL 为 Button。
4. 再通过左侧 Form 菜单返回，模型恢复空值，结果“尚未提交；活动校验：0”，未显示旧用户名错误。输入 admin 并点击提交，再次从活动校验 2 完成为“通过；活动校验：0”。[返回后新提交证据](./evidence/cedar-form-batch103.png)。

第一次尝试离开时页面没有切换，URL 仍是 Form 的页内锚点，旧校验随后结束；该尝试不算在途清理通过。第 3 步重新进入后重做，明确核对活动计数、Demo 消失和目标路由。浏览器只能证明返回后的可见状态与新事务正常，不能单独证明所有后台定时器已释放；资源清理另看自动测试。

## 范围与同步

- 未确认新的组件缺陷，本批无源码、Demo、CSS 或 API 改动。现有中文 Form 文档说明原生提交/重置和卸载清理，保持不覆盖现有文档改动；主验收索引同步新增实测边界。
- Maple 当前 Form 示例中尚无真正异步规则的对应 Demo；不把同步规则、显式 validating 外观或 Cedar 结果记为 Maple 通过。需要后续增加可明确控制返回顺序的本地异步 Demo，再验收并发新旧提交与动态字段竞争。
- 两端菜单/调研一致性检查通过：72 族，56 已同源、15 逻辑已同源、1 独立，Form 仍为逻辑已同源，不能理解为全部高级交互已覆盖。
- 本批未重跑类型、lint 或完整构建（无源码变化，使用已有构建站）；保留脏仓库及其他聊天变更，不提交、推送或发布。
- 额外观察校验期间提交按钮：原生 disabled=true、loading 类存在；最后重置恢复“已重置；活动校验：0”。async-demo 与 form-controller 两文件 7 项自动回归通过，独立于上述浏览器覆盖；design-ui `git diff --check` 通过。
- 未覆盖：Maple 真异步规则、可控乱序提交返回、动态字段删除/重排中的异步校验、跨字段依赖变化、KeepAlive 的浏览器真实停用。以上不标记通过。
