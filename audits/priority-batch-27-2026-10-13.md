# 第二十七批：真实 Demo 交互验收（进行中）

验收对象为生产文档站点，Cedar 4183、Maple 4184。挂载成功不计为交互通过；下表只记录已观察到的状态，不代表组件全部 Demo 或所有组合均已验收。

## 进度统计快照（2026-10-15，第 108 批后）

用户随后明确要求本聊天任务持续运行直到其说停止：取消原今晚 00:00 和连续 24 小时截止，每 10 分钟接续。全部已授权验收完成后报告并待命，不制造重复工作；用户叫停时安全收尾并停用。其他聊天的 Token 自动化不在本次修改范围。

同源计划以 component-reuse.json 的 72 个跨端组件族为分母：完整同源 56（77.8%）、逻辑同源 15（20.8%）、按设计独立 1（1.4%）；三类待实施均为 0。需对齐的 71/71 族已归档为完成（100%），这是分类与对应源码门禁范围，不是所有行为/页面验收完毕。

真实交互采用更保守、可复核的登记口径：仅将下表中有独立交互记录的名称匹配到 72 族，拆开 CountTo/Countdown、TimePicker/TimeRangePicker、Checkbox/Radio，合并 Drawer/Popup 为同一族，排除 Code 静态视觉。得到至少一端有部分交互证据 37/72 族（51.4%），其中两端都有部分交互记录 33/72（45.8%）；另外 35/72（48.6%）尚无下表独立族级记录，不等于已有缺陷或从未被其他组件间接覆盖。Scheduler、Tree 等单端特有组件不在此 72 族分母中，不能据此推导整库验收率。

这些是“有部分证据的组件覆盖率”，不是“所有 Demo/场景完成率”。尚无穷举场景矩阵，不提供臆测的总完成百分比。下一步应补齐缺少独立记录的组件族，并继续当前高级异步/拖拽边界，不应仅重复少数组件已通过的基本动作。静态组件按视觉/语义记录，基础层经调用方覆盖需另行映射，不伪装成独立交互。

第 107 批后完整生产文档构建仍受两端 Token 文档解析错误阻塞，第 107/108 批修复后证据来自源码开发站；此前主表的生产站总述不代表最新完整构建通过。详见各批证据。
